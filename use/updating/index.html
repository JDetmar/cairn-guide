Updating the firmware

A firmware update comes as one file, signed with Cairn’s release key and named for the board, the version, and the build, such as waveshare-s3-epaper-154-0.3.0-1a2b3c4d.fw. The recorder installs only a file signed with that key and made for its own board, and only one newer than the firmware it runs. Each comes from a GitHub Release of the Cairn repository, with the file attached and its SHA-256 in the release’s notes; CI made and signed it, as “Releasing an update” in firmware/README.md describes.

Copying an update to the card

Section titled “Copying an update to the card”
  1. Let the device go to sleep, take the card out, and copy the file into /cairn/update/ on it. Leave the file’s name as it is: the device installs a file only under the name it was signed with.
  2. Put the card back, and wake the device with Tag. If the device shows No card, putting the card back is enough.

A wake by Record never starts an update: it always records first. The device installs the update by itself as it wakes, unless the battery reads below the threshold for a sync, 3,500 mV on the recorder, or the wake before ended because the battery gave out. A board that can tell when it is charging installs while it charges whatever the battery reads; the recorder cannot tell, so the threshold applies while it charges too. A low battery shows Battery low, and the update waits on the card for a later wake.

What the screen shows

Section titled “What the screen shows”

While the device installs the update, the panel shows Updating and Keep the card in. The bar under Updating fills a quarter at a time as the device writes the new firmware. Leave the card in, and the device alone; on the recorder it takes about half a minute, most of it writing the new firmware. Then the device restarts by itself into the new firmware, which checks itself on that first start: the card, the settings, the notes on the card, and that audio comes in, as it does for a recording. If all is well, it shows Updated and New firmware runs, and from then on that firmware stays. If the new firmware fails its check, or stops before it has finished, the device goes back to the old firmware by itself and shows Update undone and Old firmware runs. The new firmware also checks the firmware it would go back to, and goes back to it at once, with Update undone, when that firmware is older than 0.3.0: firmware from 0.3.0 on keeps what later firmware adds to the card and the device, and older firmware does not. To update a device that runs firmware older than 0.3.0, install 0.3.0 first, and then the newer file. Your notes are safe either way: an update never touches queue/ or poison/, and a recording made on either firmware waits for the hub as usual.

If you press Record during an install, the device stops the update and starts recording at once, and the update waits for the next time you wake the device with Tag. If the device had already finished writing the new firmware when you pressed, the update cannot stop: the device records all the same, and once the recording is over, with its tagging window and any sync after it, it restarts into the new firmware. If you take the card out during an install, the update stops, the old firmware keeps running, and the device shows Update failed. If the card came out before the device had begun to write the new firmware, the file keeps its .fw name and installs on a later wake.

What the file’s name says afterwards

Section titled “What the file’s name says afterwards”

The device never deletes an update file. Instead it adds a word to the file’s name that says what happened to it:

The name ends in What happened What to do
.fw It waits to be installed. Wake the device with Tag.
.fw.installing An install was under way when the device lost power or was reset. Wake the device, which works out what happened and renames the file.
.fw.applied It installed, and the new firmware runs. Nothing. Delete the file whenever you like.
.fw.rolled-back It installed, but the new firmware failed its check, so the old one runs. Read the update lines in /cairn/log/boot.log, and try again only once you know why.
.fw.interrupted The install stopped part way, as when the card came out or the power went, and the old firmware runs. Try again.
.fw.refused The device would not install it, for the reason in /cairn/log/boot.log. See Why a file was refused.

Trying again

Section titled “Trying again”

Once the device has renamed a file, it never tries that file again by itself, unless a press of Record stopped its install. To try a file again, rename it so that it ends in .fw, by deleting what follows .fw, then put the card back and wake the device with Tag. If update/ holds another file of the same name with another ending, move that one off the card first: the device skips a file while a name it would rename that file to is taken.

Why a file was refused

Section titled “Why a file was refused”

/cairn/log/boot.log has an update line for each step of an update, and the reason= on a refused line says why:

reason= Why What to do
format The file is not an update, or is cut short. Copy it again.
name The file was renamed. Give it back the name it came with.
board The update is for another board. Use the file made for this board.
too-big The update does not fit the device. Nothing; this update cannot be installed.
older It is older than the firmware that runs. Nothing, unless you want to go back: that needs a file signed to allow it.
current It is the firmware that runs. The device shows no notice for it. Nothing.
key It is not signed with Cairn’s release key. Use a file signed with it.
damaged Its bytes are not those that were signed, perhaps from a bad copy. Copy it again.
